> 目的：找出别人已经踩过的坑和验证过的写法，避免我们重复试错。
> 分析对象（均为已订阅的创意工坊模组）：

> - `3811135790` 北元战国世 R23H.1 FINAL（同一模组的调参版）

## 一、北元战国世：架构

### 规模与切分

- **31 个中华势力**，写在 `main_menu/setup/start/zhonghua_countries.txt`（5705 行）
- 每个势力直接列 `own_control_core`，一地一行，按府州加了中文注释
- 国家定义是**整文件覆盖** `in_game/setup/countries/00_east_asia.txt`（1458 行）
- 另有 `in_game/map_data/`：`locations.png`、`adjacencies.csv`、`default.map`、`location_templates.txt`
  ——他们**改了地图**，这是 161MB 的主要来源

### 关键判断

| 做法 | 评价 |
|---|---|
| 31 个势力而非 100+ | AI 与外交界面压力小，节奏更像战国；我们做 100 需要在性能上另想办法 |
| 整文件覆盖 `00_east_asia.txt` | 维护成本高，每次官方更新都要重新合并。我们用「新增文件 + 新增 TAG」更安全 |
| 改地图 | 我们**不要碰**。改地图意味着永久锁死在某个版本，且工坊更新极易冲突 |
| `setup/start/` 路径 | 那是 1.3 的目录名；1.4.2 已改为 `setup/1337/`。这解释了他们为何卡在 1.3 |

### 局势系统（6 个）

`northern_yuan_warring_states`（395 行）是最核心的：

```
can_start = {
    international_organization:middle_kingdom = { var:celestial_authority <= 20 }
    OR = { current_year >= 1555  NOT = { exists = c:CHI } ... }
}
```

**要点：用「天命权威 ≤ 20」作为天下大乱的触发器**，而不是写死年份。这比我们现在的 `current_year >= 1337` 高明——它让「朝廷虚弱」成为因，割据成为果。

`can_end` 里有一个很巧的写法：

```
custom_tooltip = {
    text = ZT_formable_china_tt
    always = no
}
```

`always = no` 的条件**永远不成立**，但 tooltip 会显示出来。作用是：在局势面板上告诉玩家「这件事可以结束局势，但你还没做到」。这正是我们「称王 / 受禅」条件提示需要的东西。

`on_start` 里用全局变量列表给势力排名：

```
every_country = { limit = { has_reform = ... } add_to_global_variable_list = { name = eligible_ZT_list target = this } }
ordered_in_global_list = { variable = eligible_ZT_list  order_by = { add = military_strength  add = monthly_income_trade_and_tax }  max = 1 ... }
```

算出**最强 / 第二强 / 第三强**，存进局势变量。这是 `受禅`、`统一`、`AI 选择目标` 的基础设施，我们迟早要用。

### 割据政权的身份：自定义政府改革

`ZT_warring_states_reforms`：

```
potential = { NOT = { has_or_had_tag = CHI }  has_reform = ...  NOT = { is_leader_of_... } }
country_modifier = {
    antagonism_received_modifier = -0.05
    win_war_chance_threshold = -0.3
    peace_offer_fairness = -3
    antagonism_tolerance = 15
    global_levy_size_modifier = 0.1
    aggressiveness_modifier = 0.1
    expected_warscore_modifier = 0.3
}
```

这套数值是「让 AI 敢打、打了不容易被全天下围殴」的调参，可以直接借。注意 `antagonism_tolerance = 15` 是关键——没有它，藩镇互吞会瞬间把恶名顶满。

### 诸侯地位：用 IO special status 而非改革

`international_organization_special_statuses/middle_kingdom.txt`（400 行）里定义了
`inner_zhuhou_state`（内藩，上限 12）与 `outer_zhuhou_state`（外藩，上限 6）：

```
inner_zhuhou_state = {
    priority = 12
    max_countries = 12
    modifier = { country_cabinet_efficiency = 0.1  monthly_legitimacy = 0.05 ... }
    map_color = define:NMapColors|HRE_ELECTOR_COLOR
    special_status_power = { value = 30 }
}
```

**这是「藩镇」最正统的表达**：它是中华 IO 内部的身份，能上色、能限额、能给修正、能被剥夺。
比我们原计划用 `warring_state`（原版红巾军用的战国改革）更贴题，也不跟原版抢定义。

### 战争与和约

- wargoal `conquer_shanxi_province`：`type = superiority` + `allowed_locations` 限定只能割**山西 area 内、且与胜者相邻**的地
  → 这就是「整合地区」的正确实现：不是给全图割地权，而是给**一块指定区域**的割地权
- `peace_treaty unified_failure_peace_treaty`：`cost = 100`，`potential` 限定 `casus_belli:cb_chinese_unification2`，
  `allow` 用「胜者是否最强 / 败者是否第二强」来卡
  → 用变量做和约准入，比用国家 tag 硬编码灵活

## 二、逐鹿中原：国号与王朝周期（最值得抄的一份）

### 改国号的正确写法

他们用**决策**（decisions）实现「称王」，条件完整：

```
potential = {
    NOT = { tag = CSO }  ...        # 排除红巾军体系国家
    country_rank = country_rank:rank_kingdom   # 王国级及以上
    NOT = { is_subject = yes }
    is_subject = no
    num_locations >= 20             # ★ 真实存在的触发器
    capital.region = region:north_china_region
    NOT = { has_variable = cdy_renamed }        # 一生只能改一次
}
```

效果不是 `define_unique_country_tag`，而是：

```
change_country_name = cdy_dn_han_kingdom_scripted_country_name
```

配合 `common/scripted_country_names/`：

```
cdy_dn_han_kingdom_scripted_country_name = {
    country_trigger = {
        has_country_modifier = cdy_breakaway_era
        has_variable = cdy_chosen_han
        country_rank = country_rank:rank_kingdom
    }
    capital_trigger = { }
    location_trigger = { }
}
```

**这才是国名的正解**：`scripted_country_names` 决定 `name_key`，`change_country_name` 只是把某个
具体键写进去；而 `customizable_localization` 只管**渲染规则**，管不到 `name_key`。
两套东西各司其职，不能混用。

### 一个必须知道的坑（他们写在注释里）

> `country_name_construction` 是**全局唯一定义**，原版在同名文件中定义。
> 若只写自己的条目，会**整个替换**原版定义，导致所有国家失去国名。
> 因此本文件 = 本 mod 的条目 + 原版全部条目（原样保留）。

也就是说：**想改国名构造，必须把原版那一整份 `customizable_localization/country_name_construction.txt` 抄进来再追加**，
否则全世界国家名全变 key。这是一个会让人查一整天的坑。

### 国号防撞名

AI 择号时，把「已用过的号」记在**局势变量**上（`situation:chinese_dynasty = { has_variable = cdy_name_han }`），
并且用 `else_if` 链顺序找第一个没被占用的号。这解决了「十个势力同时叫楚国」的问题。

## 三、我们可以直接借的 8 条

1. **局势 `can_start` 用 `celestial_authority <= 20` 判定天下大乱**，别写死年份
2. **`custom_tooltip + always = no`** 做「条件未达成」提示，用于称王/受禅面板
3. **全局变量列表 + `ordered_in_global_list`** 算最强/次强，供受禅与 AI 使用
4. **自定义政府改革**做割据政权身份，数值直接抄（尤其 `antagonism_tolerance = 15`）
5. **IO special status** 做「藩镇/诸侯」，比改革更贴题、可上色、可限额
6. **`allowed_locations` 限定区域**实现「整合地区」CB，而不是全图割地
7. **`scripted_country_names` + `change_country_name`** 才是改国号的正确姿势
8. **`num_locations >= N`** 是真实可用的触发器（我们之前不确定的 `num_of_owned_provinces` 可以弃用）

## 四、我们必须避开的 4 个坑

1. **`setup/1337/*.txt` 不能带 BOM**（我们已踩，导致整个文件解析失败）
2. **`country_name_construction` 是全局唯一键**，改它必须整份复制原版
3. **不要改地图**，会把模组锁死在单一版本
4. **不要整文件覆盖原版 setup / 国家定义**，尽量新增键

## 五、与他们路线的差异（我们的取舍）

| 维度 | 北元战国世 | 我们 |
|---|---|---|
| 势力数 | 31 | ~100（更碎，但要控 AI 性能） |
| 宋的形态 | 未涉及 | **建筑国家**，无地虚君，独一无二 |
| 元 | 被消失 | **保留为北方帝国**，可反杀，带绿巾军双结局 |
| 地图 | 重画 | 不动 |
| 定义方式 | 覆盖原文件 | 纯新增键 |
